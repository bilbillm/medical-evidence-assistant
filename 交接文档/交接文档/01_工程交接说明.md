# DEAP 医疗智能体工程交接说明

更新时间：2026-07-03

本文档只用于工程交接，说明当前 DEAP 医疗智能体已经配置了什么、接手人需要继续做什么、需要使用哪些文件。本文档不包含讨论过程、思路复盘或经验沉淀。

## 1. 项目当前状态

项目名称：医检证据助手

项目平台：钉钉 DEAP 智能体平台

当前已完成主线：报告文字输入闭环。

当前已完成能力：

1. 用户粘贴脱敏后的检查报告文字。
2. 智能体提取检查类型、检查部位、关键发现、诊断建议和原文依据。
3. 智能体判断资料状态：normal / abnormal / uncertain。
4. 智能体根据诊断建议关键词追问缺失资料。
5. 智能体生成医生查看版资料包。

当前未完成但需要接手人继续做的重点：

1. 跑完整 DEAP 智能体评测。
2. 收紧医生查看版资料包的安全措辞。
3. 确认发布、权限和演示入口。
4. 增加 OCR / 图片入口能力。
5. 增加“医生资料包集中呈现”体验。

## 3. 接手人下一步任务

### 任务 1：跑完整智能体评测

目标：
验证当前 Prompt + 知识库在 DEAP 评测环境下是否稳定。

怎么做：

1. 进入 DEAP 智能体评测。
2. 选择当前“医大智能体”或对应智能体。
3. 选择 `医检证据助手-MVP文字闭环评测集`。
4. 运行评测。
5. 记录失败样例、输出偏差和需要修正的 Prompt/知识库位置。

完成标准：

- 主要 normal / abnormal / uncertain / 医生资料包样例能按预期输出。
- 失败样例有记录，不要求一次性全部修完。

### 任务 2：收紧医生查看版资料包安全措辞

目标：
让最终输出保持“资料整理”定位，不变成诊断、治疗或复查建议。

重点检查：

- “建议向医生确认的问题”是否只写成问题。
- 是否出现穿刺、手术、用药、复查周期等具体决策建议。
- 是否出现良恶性概率、严重程度判断、吓人或绝对化表达。

禁止表达：

- 通常建议穿刺。
- 多数为良性。
- 恶性风险较高/较低。
- 多久复查。
- 重复超声、穿刺等。
- 随访周期及复查方式应如何制定。

推荐固定问题：

1. 当前报告中的异常提示需要结合哪些病史、体格检查或原始影像信息判断？
2. 是否需要补充相关检查，请医生结合情况判断。
3. 是否需要进一步检查或随访安排，请医生结合原始影像和临床资料判断。

### 任务 3：确认发布和演示入口

目标：
确保项目可以被评委或演示人员打开、测试和录屏。

需要检查：

- 智能体是否保存到最新版本。
- 知识库文件是否全部启用。
- 发布入口是否可用。
- 分享链接或控制台演示路径是否可记录。
- 权限是否设置正确。
- 多轮会话是否开启。
- 长期记忆是否关闭，避免保存医疗隐私。

### 任务 4：增加 OCR / 图片入口能力

这是接手人需要继续补的功能，不是已经完成的功能。

目标：
让用户除了粘贴报告文字外，也能上传报告截图或图片资料，并让智能体尽量提取文字信息。

建议先做的范围：

1. 报告截图 OCR：
   - 上传清晰脱敏报告截图。
   - 提取报告中的检查所见、描述、诊断建议、提示、结论。
   - 如果识别失败，要求用户粘贴报告文字。

2. 低清晰度图片兜底：
   - 测试低清晰度、遮挡、倾斜、截图不完整的报告图片。
   - 识别不稳定时，不要硬编内容。
   - 要提示用户补充清晰图片或粘贴文字。

3. X 光、CT、MRI 等影像图片入口：
   - 先确认这是什么检查类型。
   - 再确认目标部位是否和用户本次诉求一致。
   - 再询问是否有配套报告文字。
   - 不要直接根据影像图片作诊断。
   - 医生查看版资料包里要区分“用户上传影像图片”和“报告文字提取结果”。

完成标准：

- 对报告截图能稳定提取关键文字，或能明确失败并要求用户粘贴文字。
- 对 X 光、CT、MRI 等影像图片，能先确认检查类型、目标部位和是否有报告文字。
- 不把图片识别内容当成医生报告结论。

### 任务 5：增加医生资料包集中呈现体验

目标：
资料收集完成后，把给医生看的内容集中放到一个好找、好复制、好转交的位置。

建议做法：

1. 生成前先输出“患者确认版”，让用户确认报告信息、症状、既往史、已做检查是否准确。
2. 用户确认后，再生成正式“医生查看版资料包”。
3. 医生查看版资料包使用固定标题：

```text
【医生查看版资料包】
```

4. 资料包不要散落在多轮对话中。
5. 后续可评估导出 Word、PDF、固定入口或医生端查看区。

当前阶段不建议先做后台数据库或医生端登录系统。

## 4. 不要改错的边界

### 4.1 OCR 要做，但不能破坏文字输入闭环

接手人需要继续增加 OCR / 图片入口能力，但不要把 OCR 改成唯一入口。已有文字输入闭环已经跑通，应继续保留。

正确理解：

- 文字输入是当前稳定主线。
- OCR 是接手人要补的下一阶段功能。
- OCR 失败时必须能回退到“请粘贴报告文字”。

### 4.2 智能体不是影像诊断系统

即使后续支持上传 X 光、CT、MRI 等图片，也只能做资料整理和资料确认，不应输出影像诊断结论。

### 4.3 不要写入敏感凭证

不要把以下内容写入公开文档、截图或聊天记录：

- Client Secret
- access_token
- SSOSecret
- API-Key
- 真实姓名
- 手机号
- 身份证号
- 门诊号
- 住院号
- 检查号

## 6. 最短接手路径

如果接手人时间很紧，按这个顺序做：

1. 读 `01_工程交接说明.md`。
2. 检查 DEAP 当前智能体是否使用 `02_DEAP配置文案/deap_persona_integrated_prompt.md`。
3. 检查知识库是否包含 `03_知识库文件/` 下的文件。
4. 用 `04_评测集/医检证据助手-MVP文字闭环评测集.xlsx` 跑一次评测。
5. 修医生资料包安全措辞。
6. 确认发布和演示入口。
7. 开始补 OCR / 图片入口能力。
8. 补医生资料包集中呈现体验。
