# 新增待实现需求记录：患者就诊准备卡展示未问病史问题

记录人：Oliver / Codex 协作
记录日期：2026-07-11
当前状态：已实现并通过自动化测试

## 1. 要做的目标

在最终“患者就诊准备卡”的“四、医生可能会追问你的信息”栏目中，展示 4-5 个问题。

这些问题应来自预先规定的“现病史、既往史问题池”，并且优先展示本轮访谈中没有问到、但医生就诊时可能继续追问的问题。

## 2. 问题池范围

### 2.1 现病史问题池

后续应围绕以下范围设计问题：

1. 起病情况与时间。
2. 发病诱因。
3. 主要症状和发病过程。
4. 伴随症状和阴性鉴别症状。
5. 诊疗经过，包括诊治单位、检查结果、治疗措施、用药情况及治疗效果等。
6. 目前一般状况，包括饮食、睡眠、大小便、体重变化等。

### 2.2 既往史问题池

后续应围绕以下范围设计问题：

1. 曾患病及长期用药史。
2. 手术外伤史。
3. 食物药物过敏史。
4. 传染性疾病史。
5. 输血史。
6. 预防接种史等。

## 3. 原因

当前“医生可能会追问你的信息”栏目偏通用提醒，后续希望它更像“就诊前补充问题卡”。

这样做的价值是：

1. 避免重复展示已经在访谈阶段问过的问题。
2. 让患者知道自己还有哪些病史信息可能需要提前准备。
3. 把前面访谈的问题限制机制和最后患者展示结果连接起来，形成更完整的闭环。
4. 更符合真实问诊逻辑：医生不是只看报告，还会补问现病史、既往史、用药史、过敏史等背景信息。

## 4. 建议实现方式

### 4.1 轻量实现

先在 `交接文档/交接文档/03_知识库文件/basic_question_bank.md` 中补充上述“现病史、既往史问题池”。

再修改 `apps/api/src/modules/mock-ai.gateway.ts` 中生成患者就诊准备卡的 Prompt，要求：

1. 第四栏必须从现病史、既往史问题池中选择问题。
2. 必须优先选择本轮访谈中未问到的问题。
3. 展示 4-5 个问题。
4. 不要重复已经问过的问题。
5. 问题要用患者能理解的大白话表达。

### 4.2 稳定实现

如果后续希望输出更稳定，建议为问题池增加结构化标签，例如：

```text
[现病史-起病时间]
[现病史-发病诱因]
[现病史-主要症状]
[现病史-伴随症状]
[现病史-诊疗经过]
[现病史-一般状况]
[既往史-长期用药]
[既往史-手术外伤]
[既往史-过敏史]
[既往史-传染病史]
[既往史-输血史]
[既往史-预防接种]
```

访谈阶段记录已经问过的问题标签，最终生成患者就诊准备卡时，把“未覆盖标签”传给模型，再由模型生成 4-5 个患者可读的问题。

需要关注以下文件或模块：

8. 自动化测试已覆盖问题池解析、标准问法、已问/主动提供差集、剩余数量边界、全覆盖提示和原四步连续流程。
