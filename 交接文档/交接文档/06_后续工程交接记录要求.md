# 后续工程交接记录要求

用途：接手人每完成一轮 DEAP 配置、Prompt 修改、图片能力测试、病程分析测试或发布检查后，必须按本文档记录交接信息，方便继续提需求、继续迭代，不让项目状态断档。

当前阶段的核心目标：

1. 收集患者资料：围绕报告文字、上传图片、症状、持续时间、既往史、家族史、用药史、既往检查和医生已给出的意见，逐步补齐资料。
2. 分析病程并展示：基于已收集资料生成患者易懂版病程分析和医生查看版资料包。

当前工程限制：

- 目前主要能控制的是 DEAP 的“人设/系统提示词”。
- 如果 DEAP 模型或对话框不支持读图，Prompt 只能要求用户补充清晰图片或粘贴报告文字，不能保证真正 OCR。
- 图片能力必须通过右侧 chat 预览实际验证，不能只凭配置说明判断可用。

适用场景：

- 修改 DEAP 智能体系统提示词。
- 调整患者资料收集流程。
- 增加或测试报告截图、化验单、病历图片识别。
- 测试 X 光 / CT / MRI / 超声原始影像图片的安全边界。
- 调整患者易懂版病程分析输出。
- 调整医生查看版资料包输出。
- 跑现有评测集或进行右侧 chat 手工测试。
- 修改发布、权限、分享入口。
- 后续增加 OCR 工具、知识库、评测集、导出 Word/PDF 或医生端查看区。

### 1.7 测试结果记录

每次改动后必须记录测试结果。

现有评测集路径：

```text
交接文档/交接文档/04_评测集/医检证据助手-MVP文字闭环评测集.xlsx
```

现有评测集只能覆盖 MVP 文字闭环，适合作为回归测试。它不能充分证明图片识别和病程分析展示已经完成。

右侧 chat 预览测试方法：

1. 保存最新系统提示词。
2. 刷新右侧 chat 预览，清空上下文。
3. 打开评测集，复制某一行“用户输入”。
4. 粘贴到右侧 chat 并发送。
5. 对照同一行“期望结果”和“评分标准”判断通过/失败。
6. 每个独立场景测试前刷新 chat，避免上下文污染。
7. 对连续流程场景可以不刷新，例如异常报告 → 补充信息 → 生成病程分析 → 生成医生查看版资料包。

记录格式：

```text

| --- | --- | --- | --- | --- | --- | --- |
| 正常报告 | 文字 | 评测集/chat |  |  | 通过/失败 |  |
| 异常报告 | 文字 | 评测集/chat |  |  | 通过/失败 |  |
| 缺少诊断建议 | 文字 | 评测集/chat |  |  | 通过/失败 |  |

| 患者易懂版病程分析 | 文字+补充信息 | chat |  |  | 通过/失败 |  |
| 医生查看版资料包 | 文字+补充信息 | 评测集/chat |  |  | 通过/失败 |  |
```

至少要测：

- 正常报告。
- 异常报告。
- 报告缺少检查所见。
- 报告缺少诊断建议。
- 患者补充症状后生成病程分析。
- 医生查看版资料包。
- 清晰报告截图。
- 低清晰报告截图。
- X 光 / CT / MRI 原始影像图片。
- 图片识别失败兜底。
- 用户追问诊断、治疗、穿刺、手术、用药、复查周期时的拒答和转写。

必须如实记录遗留问题，不要为了显得完成而隐藏问题。

记录格式：

```text
遗留问题：

1. 问题：
   影响：
   当前判断：
   建议下一步：

2. 问题：
   影响：
   当前判断：
   建议下一步：
```

常见遗留问题示例：

- DEAP 当前模型或对话入口无法读取图片内容。
- OCR 对低清晰图片不稳定。
- 原始 X 光/CT/MRI 图片无法稳定识别资料类型。
- 病程时间线在日期缺失时不够清楚。
- 患者易懂版仍偏专业。
- 医生资料包仍偶尔出现医疗建议化表达。
- 评测集只覆盖文字闭环，缺少图片和病程分析样例。
- 发布入口或权限未确认。

## 3. 最重要的交接要求

接手人做完后不能只说“功能完成了”，必须交付：

1. 改了什么。
2. 在哪里改。
3. 为什么改。
4. 怎么复现。
5. 用哪些测试样例验证。
6. 测试结果。
7. 截图证据。
8. 遗留问题。
9. 下一步建议。

这样后续才能继续提需求、继续迭代。
